# 机器人适配层契约

`RobotDriverAdaptor` 是程序内唯一允许业务代码依赖的机器人接口。机器人品牌、SDK、
控制器状态码、程序格式、寄存器、原生速度单位和通信细节必须留在派生驱动内部。

## 分层规则

- `src/` 中除机器人驱动实现和控制单元工厂外，不得包含具体机器人驱动头文件、具体驱动类、厂商 SDK 状态码或 `dynamic_cast` 到具体驱动。
- 业务运动统一调用 `MoveLinearMmPerMin`、`MoveCircularMmPerMin`、`MoveJointPercent`、轨迹生命周期接口和标准状态接口。
- `MoveLinearMmPerMin`、`MoveCircularMmPerMin`、`MoveJointPercent` 的成功返回只表示控制器已经受理命令且适配层已冻结运动身份，不能在接口内部阻塞到运动完成；业务层必须继续采样并通过 `CheckRobotDone` 获取自然完成见证。这样扫描、标定和传感器采集才能与真实运动并发执行。
- 直线速度统一为 `mm/min`，关节速度统一为百分比；厂商单位换算由派生驱动完成。
- 业务判断统一使用 `RobotMotionState`，不得解释厂商原始状态码。`rawCode` 只用于日志和诊断。
- 新功能先扩展适配层契约，再由各品牌驱动实现；不得在业务层增加品牌分支。
- 品牌驱动只能在 `RobotDriverRegistry` 登记；`ContralUnit`、配置页和业务页不得包含具体驱动头文件。
- 适配层只声明功能，不保存或实现品牌通信协议。SDK、Socket、FTP 客户端、账号、控制器目录和程序扩展名
  必须由品牌驱动持有，并由品牌驱动组合调用独立底层组件。
- 连接统一调用 `Connect`/`Disconnect`；业务层不得读取 Socket 配置或调用 `InitSocket`。
- 机器人文件功能统一通过 `CreateFileTransferSession` 返回的适配层会话调用。业务层不得包含或创建
  `FtpClient`，会话 DTO 不得携带 FTP 账号或密码。
- `InitSocket`、`InitFtp`、`UploadFile`、`CallJob`、`MoveByJob`、`ContiMoveAny` 等协议/程序级钩子
  不属于适配层，必须只存在于品牌驱动及其底层组件中。
- 机器人名称、类型、轴单位、运动学参数、工具、外部轴和日志等运行时状态同样通过查询、设置或写入
  接口访问；业务层不得直接读写适配器或品牌驱动成员。

## 强制实现与能力声明

新增机器人驱动必须继承 `RobotDriverAdaptor` 并实现全部纯虚函数。即使某项硬件不支持，
也必须显式返回失败、填写 `GetLastRobotError()`，并且不得声明对应能力。

`DriverCapabilities()` 只声明已真实实现且可以验证终态的能力。业务层按能力开放入口；
没有能力时必须在运动或状态变更前关闭入口或 fail-closed。

完整先测后焊至少需要以下能力：

- `PassiveState`、`LinearMotion`、`JointMotion`
- `ContinuousTrajectory`
- `VerifiedProgramCompletion`、`VerifiedSafeAbort`
- 需要扫描/焊接暂停和断点恢复时：`PauseResume`、`PersistentProgramRecovery`
- 需要真实起弧时：`ActualArcWeld`
- 需要离线生成控制器程序时：`OfflineTrajectoryExport`
- 使用外部轴时：`ExternalAxis`

手眼辅助程序安装、机器人侧手眼验证、连续长按点动、原生程序上传和诊断命令属于独立能力；缺少它们只关闭对应功能，
不得影响通用运动、扫描和焊接业务调用路径。

连接/断开、报警复位、伺服上下电、工具读取、整数/实数寄存器读写、圆弧运动、结构化控制器状态、
示教速度、受验证原生程序执行、FTP、
机器人手眼矩阵读取也分别使用独立能力位。管理测试、CLI、示教和诊断入口与生产流程遵守同一规则：
能力缺失时在调用品牌底层前禁用或拒绝，并显示具体缺失能力。

## 轨迹生命周期

业务层只使用以下生命周期：

1. `ReserveTrajectory` 冻结程序身份。
2. `DownlinkTrajectory` 生成并下发程序。
3. `StartTrajectory` 启动同一程序身份。
4. `WaitTrajectory` 返回标准终态和可验证完成见证。
5. 任何未知、超时或取消路径调用 `AbortCurrentProgramSafely`，只有稳定终态见证成功才可解除运动闭锁。

暂停/恢复必须绑定 `GetTrackedMotionIdentity` 返回的同一程序身份，恢复前还要校验暂停位姿偏差。
不能证明程序身份或自然完成时，不得把停止态当成成功。
`StartTrajectory` 不得隐式重新生成或上传；STEP 的 SRP/SRD 内容哈希和大小在 Downlink 时冻结，
Start 前必须再次核对本地内容并回读远端内容，确认一致后才能加载和启动。

## 新机器人接入清单

1. 在驱动层实现全部纯虚函数，并完成标准单位、状态和错误信息转换。
2. 仅为已验证功能设置能力位；真实焊接能力必须包含起弧、灭弧及焊接完成证明。
3. 只在 `RobotDriverRegistry` 登记新驱动，并填写 `RobotDriverSetupProfile` 的独立 `templateId`、端口、
   监控通道、FTP、控制器工程与本地任务目录元数据；`templateId` 只能是稳定的品牌模板身份，禁止使用
   `RobotA/RobotB/RobotC` 等实际控制单元名。注册表会向控制单元工厂和配置界面公开已安装品牌，业务页面无需增加品牌分支。
4. 运行 `python scripts/tests/verify_robot_driver_adaptor_boundary.py`，确认业务层没有越过适配层。
5. 运行机器人专项安全测试和 Release 编译。
6. 上真实机器人前分别验证连接、读状态、单点运动、轨迹完成、安全中止、暂停恢复和断电/重启恢复。

满足全部纯虚契约并声明业务所需的全部能力后，新机器人可复用现有程序功能；只满足部分能力时，
程序只开放已声明能力覆盖的功能，不允许用默认成功或品牌判断绕过缺失能力。

## 统一适配验收流程

“调试/机器人适配测试”是所有机器人品牌共用的独立现场验收入口；原“功能测试”页仍保留单项诊断，
两者可切换到同一受互锁保护的测试页面。业务页只调用
`RobotDriverAdaptor` 与其文件传输会话，不包含品牌驱动头文件或品牌协议判断。每轮记录按机器人名称和
运行编号保存在数据库 `robot/<RobotName>/RobotAdaptorAcceptance`，保留能力掩码、各阶段状态和人工/自动证据；
真实机器人位姿断点不跨页面或进程恢复。

验收入口采用独立的主从调试界面，不再把“单项测试/机器人适配测试”页签暴露给现场人员：顶部下拉框选择
当前工程中的机器人实例，左侧固定显示全部验收流程，右侧随流程切换对应的说明、能力/前置门禁、可编辑参数、
自动与人工证据及“开始测试”等操作按钮。切换机器人时会同时切换适配层驱动、相机缓存、数据库验收轮次和
参数记录；硬件操作或全局机器人互锁有效期间禁止切换，防止把一个机器人的结果写到另一个机器人名下。

测试报告不以“全部通过”为导出前提：任意阶段均可点击“导出当前测试报告”，在
`Result/RobotAdaptorAcceptance/<RunId>` 原子写入同名 Markdown 和 JSON。报告包含机器人/驱动/控制端点、
能力掩码、测试参数、每阶段能力门禁、状态、完整证据和后续处理建议，不包含FTP用户密码等底层凭据。
总体状态分为 `pass`、`fail`、`restricted`、`incomplete`；能力受限、跳过或未执行不得写成通过。

验收固定为以下阶段，并逐级失败关闭：

统一定义来自 `include/RobotAdaptorAcceptancePlan.h`，当前修订为
`RobotAdaptorAcceptancePlan-20260905-v1`。机器人选择、数据库记录、Markdown/JSON报告都使用同一份阶段定义并保存该修订号。
新增机器人品牌只能注册驱动、声明能力并在适配层以下实现品牌协议；不得复制一套品牌专用测试页或改变阶段顺序。

1. 首先核对实体机器人、驱动和控制IP/端口，单独执行机器人控制连接测试：调用 `Connect` 建立连接并用
   `IsConnected` 回读确认；已有连接只复用、不主动断开。控制器状态和当前位置留在后续独立阶段验证，
   避免把连接问题与状态协议问题混成一个结果。
2. 从品牌底层默认目录有限递归查找控制器已有的专用测试 JOB；排除汇川固定入口 `main.pro`，人工确认
   非生产程序且当前未运行后，先下载，再按原路径同名回传（不做上传前删除），随后再次下载并核对
   大小/SHA-256。不新增、改名或删除工程文件；没有合适文件时提示先在示教器当前工程创建专用测试 JOB。
3. 读取当前位置并按 `WeldDryRun` 生成单点低速原生空跑程序，只执行 `ReserveTrajectory/DownlinkTrajectory`；本阶段禁止
   `StartTrajectory`，由人工在示教器确认文件可见、可加载且语法无报错。
4. 连续读取当前位置、关节脉冲、通用完成状态及品牌声明的结构化控制器状态。
5. 输入固定安全确认语后，以界面设定的低速（默认 `60 mm/min`）沿基坐标 `+Y` 单步外移，再次执行返回本次会话捕获的原始位姿。
   两段运动均进入 `RobotOperationLease` 的待确认终态；未完成返回、异常中止未确认或原始位姿丢失时不得判定通过。
6. 枚举能力并检查空闲/完成终态；INT/REAL逐个读取原值并持久化，写入测试值后等待现场确认，确认后自动回读比较，再恢复和再次回读。确认窗口由适配层提供品牌实际变量名。
   模式、伺服、报警复位和速度等会改变控制器状态的接口保留为独立单项测试，禁止一键连续触发。
7. 只读检查业务实际使用的控制器/运行时DH、轴单位、限位、界面所选工具号（默认 Tool1）、关节/直角闭环及控制器程序清单。
   声明 `ControllerKinematicsRead` 的品牌必须在底层只读获取机械数据、交叉核对独立来源，并用当前关节角和控制器直角位姿完成正解闭环；
   业务层只读取适配层校验结果。未声明该能力时只能记录受限并提示从示教器导出变量名、单位和路径，不能用其它机器人参数替代。
   控制器手眼读取属于独立可选接口；品牌未声明时不导致本阶段失败。
8. 加载本地已验证手眼矩阵，用当前相机点和当前机器人位姿执行现有二转三计算，并以已知标定块/TCP点的毫米误差人工判定精度。
9. 打开现有先测后焊流程做仅扫描/空跑，检查时间对齐、图像/点云完整性、二转三、后处理和轨迹结果。
10. 只有驱动声明 `ActualArcWeld` 且前述阶段全部通过时，才允许打开现有实际焊接流程；仍由人工复核焊机、气体、
    送丝、工艺、起收弧、掉弧处置和安全回撤，验收页不会自动开始焊接。
11. 所有阶段必须为通过才能生成完整验收汇总；跳过、能力受限或仅通信成功都不等于适配完成。

运行 `python scripts/tests/verify_robot_adaptor_acceptance_flow.py` 可检查上述阶段、FTP闭环、只下发不启动、
真机运动终态登记与返回原位、寄存器备份恢复、能力门禁和现有先测后焊入口是否仍完整。

每个品牌的 `RobotPara` 模板独立存放在数据库作用域
`robot_type_template/<templateId>/RobotPara`。模板带 `TemplateMeta/TemplateId`、`RobotType` 和修订号身份，
新建控制单元或切换品牌时只允许从匹配类型模板复制。实际机器人配置、工件模板和其他品牌模板均不得作为
回退源；品牌切换会清除旧品牌运动学、工具参数和型号绑定，强制停用该控制单元，并把相机/手眼完成状态重新置为未完成。

## 当前品牌能力边界

- FANUC 已登记；运动、轨迹完成、安全中止、FTP、原生程序上传/执行、连续点动、离线 LS/TP
  轨迹导出和手眼辅助程序均通过适配层接入。`PauseResume` 已通过活动任务精确身份、`PAUSE_TASK`/
  `CONT_TASK`、`TSK_STATUS`、`TSK_LINENUM` 和两次稳定位姿闭环接入；`ToolDataRead` 读取
  `$MNUTOOL[1,n]` 的 XYZWPR；`HandEyeMatrixRead` 约定变量 `eye` 为 `R[100]~R[111]`：
  前 9 个寄存器按行优先存放 3x3 旋转矩阵，后 3 个存放毫米平移，读取后必须通过有限值、正交性
  和正行列式校验。现场必须先上传本版本 `FanucServiceLib.pc` 并重启 `STARTALL`，旧服务会因缺少
  `LIB=20260825_ADAPTOR_V3` 能力标识而失败关闭。
- FANUC 当前仍未声明 `ActualArcWeld`、`ExternalAxis`、`OperationModeControl`、`AlarmReset`、
  `ServoPowerControl`、`CircularMotion`、`RealRegister`、`StructuredControllerStatus`。这些能力分别需要现场 ArcTool schedule/灭弧回读、多运动组或扩展轴配置、
  External Mode Select/DCS 安全链以及 UOP/安全 PLC 的动作与状态回读；在获得现场配置和终态证据前，
  相关入口必须保持关闭，不能用通信成功代替功能完成。服务器中旧的 `SET_SPEED`、加载/启动和旧运动
  命令占位 `OK` 已全部改为明确 `ERR`。现有 FANUC LS/TP 生成器只写 GP1/J1-J6，外部轴目标会
  显式拒绝，不能静默丢弃变位机坐标。
- STEP 已登记；原生 SRP/SRD/SR 上传通过适配层组合 FTP 会话实现，原生程序执行通过
  ProgramLoad/START、精确工程与程序身份、控制器错误消息、运行进度和稳定 `eStop` 闭环实现；
  自动生成的扫描/焊接轨迹仍额外保留 SRP/SRD 内容身份和 `ntdone` 自然完成见证。
  STEP `RealRegister` 已同时接入 `VariableRealReadCmd`/`VariableRealModifyCmd`，读写都按工程变量或程序变量
  作用域调用SDK。STEP手眼辅助 SRP/SRD 已可安装，但尚未声明机器人侧手眼计算结果验证；连续长按点动、
  `CircularMotion` 和 `StructuredControllerStatus` 也未声明，相关入口保持关闭并显示底层缺少的证明字段。
- 汇川已登记为 `ROBOT_TYPE_INOVANCE`，底层直接实现手册4.25.1的2222端口字符串协议：请求
  `@@command$$`、应答 `##result$$`，所有命令由单一互斥请求/应答通道串行执行，不依赖加密SDK包。
  控制入口逐项验证 `CurCtrlDev=2`、`CurPermit=1`、急停释放、故障状态、伺服状态；默认禁止强抢
  其它客户端的许可。汇川 `Connect()` 在同一socket锁内完成 `Get_ConnectState`、`UserLogin` 和
  `CurUserType` 回读后才发布连接成功；监控重连复用此路径。默认以管理级（2）和源码中的品牌默认
  密码登录，数据库 `ApiUserLevel/ApiPassword` 的有效非零级别/非空密码可覆盖。旧模板级别0及空密码
  采用品牌默认值，避免旧配置跳过登录。登录失败、应答不明确或权限不匹配时关闭连接，不降级放行。
  凭据仅留在品牌底层，不进入适配层DTO、日志或验收报告；登录拒绝也不回显控制器应答中的密码。
  登录失败保留脱敏的协议错误码，并附带固件、控制设备、API用户级别和许可归属的只读诊断。
  `e3` 仅表示参数值不合法，不能直接认定为密码错误。拒绝、应答不确定或权限回读失败后锁存错误，
  监控不再每2秒重复提交密码；连接关闭和普通查询不会清除此错误，人工点击连接测试可重试一次。
  TCP建连失败仍保留原有后台重连。SDK 4.25.2.12 的离线回环实测确认 UserLogin 使用级别和明文密码，
  无用户名、MD5或十六进制编码步骤。2026-09-04现场对照测试确认示教器所用密码被API拒绝，
  说明书示例密码则通过编辑级和管理级登录及权限回读，品牌默认API凭据已改用该实测值；
  不修改示教器密码，不静默覆盖数据库的显式凭据，登录通过不代表运动验收通过。
  自动登录不会上电、切运行模式、启动程序或选择工具/工件。后续初始化仍校验当前Tool/Wobj与配置一致，
  只有原有显式管理级配置或非零工具/工件配置才保留原先的坐标选择动作，不能由新的默认管理级隐式触发。
- 汇川当前声明连接、状态、MOVL/MOVJ/MOVC、扫描数据流轨迹、连续点动、模式切换、报警复位、
  伺服上下电、全局速度、工具读取、P位置寄存器、R/B整数寄存器、D实数寄存器、结构化控制器状态、
  同工程原生模块执行和前三个外部轴。`ServoOff` 在运动或任务活动时先执行可验证安全中止，再发送
  `Motor OFF` 并轮询 `Get_MotorSts=0`；断开流程复用同一适配层功能。
  通用 `IntegerRegister` 默认映射全局 `R0..R255`，写入使用 `Set_R` 并由 `Get_R` 回读；显式 `B/BYTE`
  映射全局字节变量，PLC_DINT只读且不会冒充可写寄存器。控制器要求 `Set_R` 在编辑模式及以上使用，
  因此通用整数写入使用连接阶段已确认的管理级权限；现场密码不同时配置 `ApiUserLevel/ApiPassword`。
  原生程序调度使用不依赖编辑登录的
  B字节状态。通用 `RealRegister` 映射全局 `D0..D255`，使用 `Get_D`/`Set_D` 并执行写后回读；
  `Set_D` 同样要求编辑模式及以上，值域限制为 `-9999999.999..9999999.999`。
  `SetIntVar` 的R/B写入、`SetRealVar` 的D写入和 `WriteCartesianRegister` 的P写入，在参数校验后、
  发送写命令前统一由品牌底层调用 `EnsureControlPermit()`，验证控制设备、获取许可并回读当前连接持有。
  非法许可归属或默认策略下其它客户端占用会阻止写入；不得依赖之前的运动或初始化恰好持有许可，
  也不得为了写变量隐式重连、上电或切运行模式。验收业务层不直接操作汇川许可协议。
  第5项寄存器验收使用共享写读恢复流程：原值读取失败时零写入；开始临时写入后即使接口失败或异常，
  仍记录实际回读并尝试恢复、恢复回读。每一步分别保存尝试状态、结果和原始错误，失败不显示为未执行，
  回读值未经读取成功不得显示默认0；失败ACK不能被后续回读改为通过。一项失败收尾后停止后续寄存器测试。
  成功写入后暂停等待示教器核对，点击“现场数值一致，回读校验”后才执行验收回读；驱动自身的写后校验仍保留，不能替代此处确认后的独立回读。
  取消、关闭确认窗口、5分钟超时或确认异常都尝试恢复且不能通过。原值在首次写入前保存至验收数据库的
  `RegisterRecovery`，只在恢复命令及回读均成功且与原值一致时清除。中断后先人工恢复再只读核对，
  校验端点/品牌且保存成功后解除恢复提示；跨验收轮次扫描未完成记录，禁止直接开始新写测试。

### 适配验收阶段 4：报警复位准备

- 用户确认现场安全并握住示教器后，低速测试先通过 `ReadControllerStatus()` 读取状态；
  对声明完整状态回读的品牌，必须确认连接有效、急停已释放、故障状态可知且已停止。
- 有报警/警告时，仅在声明 `AlarmReset` 后调用一次 `cleanAlarm()`，随后独立回读状态；
  汇川底层仍负责 `ResetErr` 及协议回读，业务层不发送原始协议。命令成功且报警/警告清除后，
  才允许切换自动模式、上电及后续原有运动验证。任何失败都不自动重试、不继续运动。
- 未声明完整状态回读的品牌不新增盲目清报警，保留原有品牌准备流程并提示人工检查。
  自动复位不能替代现场释放实体急停，也不会在界面打开、记录恢复时触发。
- 验收记录保留准备前、复位后和上电后的状态、具体故障码、复位命令及回读结果；
  未发出的模式、上电、运动或中止命令标记为“未执行”，不冒充接口执行失败。

### 适配验收阶段 4：汇川无位移模式组合（2026-09-04）

- 业务层通过 `ModePreparationTestCases / RunModePreparationTestCase / UseVerifiedModePreparation`

- 汇川提供 8 组：手动/自动 × 上电后开数据流/开数据流后上电 × 关数据流后下电/下电后关数据流。

  首次进入时按固化且“上电→开数据流”的组合切换到验收模式，等待模式稳定250ms，再最终执行/确认
  `Motor ON`并开流。正常完成只关流，保留该模式和伺服上电；后续直连段只开关数据流，不再切模式

### 显式连接后的统一前置初始化（2026-09-07）

- 用户在主页点击“连接机器人”或执行适配验收流程0时，业务层只调用
  `Connect` 和 `InitializeAfterConnect`。新建连接和后台已建立的连接都执行同一个品牌适配钩子；
  初始化失败时通信连接可保留，但界面和报告必须显示“未就绪”，不能仅凭TCP连接判通过。
- `Connect`、状态监控自动重连和只读查询保持通信/登录/只读资产恢复，不调用连接后初始化，
  避免网络抖动、程序后台启动或断开清理时自动清报警、切模式和上电。
- 汇川显式初始化按固定连接epoch执行：确认静止、主任务停止/就绪、急停解除、数据流关闭；
  确认 `CurCtrlDev=2`，普通 `AcqPermit` 获取当前客户端许可且不强抢其它客户端；
  必要时 `ResetErr` 并回读无报警；工具/工件配置写后回读；切换模式2并回读；`Motor ON`并回读。
  已满足的步骤跳过，任一步失败立即停止后续步骤，不启动程序或机器人运动。
- `Get_MotionSts=2` 必须显示为“运动已中断”，不能通过旧式完成位折叠成“运行中”。连接时只允许在
  `motor=0、Get_DsMode=0、主任务停止、无急停/故障、CurCtrlDev=2、许可未被其它客户端占用`
  的严格状态下受限恢复：先普通取得当前客户端许可，连续三次确认同一安全中断态，再执行
  `Prg Stop`；仍为2时执行 `BackStartLine`，最终必须回读 `Get_MotionSts=0` 才能继续切模式和上电。
  `motion=1`、伺服已上电、数据流未关闭或任务运行时均不得自动重置。正常安全中止若在关流后
  遗留 `motion=2`，同样必须 `BackStartLine` 并连续确认0，避免把中断态带到下一次连接。
- 汇川手册只提供 `CurCtrlDev` 查询和 `AcqPermit` 许可接口，没有把示教器“控制设备”改为远程
  以太网的设置接口。非2时必须提示在示教器/InoRobotLab切换，程序不得猜测未定义命令。
  实体急停同样不能由该流程解除。
- 显式初始化完成后保留模式2和伺服上电。首次数据流运动若固化组合要求其它模式，则等待模式切换
  稳定后再确认伺服并开流；运动完成只关流并保留伺服，后续直连段复用该状态。原生JOB启动前独立
  恢复模式2和伺服；仅断连/退出执行品牌安全收尾。
- `scripts/tests/run_inovance_connection_preparation_tests.ps1` 使用纯模拟状态机验证命令顺序、幂等、
  急停/活动任务/遗留数据流/许可占用门禁、失败短路与零运动命令。

  采样域、随机种子、训练与独立验证样本、计算请求/应答和结论。优化只调用计算接口，不切模式、不上电、

### 连接就绪与先测后焊入口（2026-09-07）

- 历史验收 `pass` 是历史证据，不是本次连接的运动许可。汇川每次建立新连接后，释放协议锁，
  按固定只读来源重新校验并装载模型、轴单位和限位。校验失败可保留控制通道，但关节运动能力
  保持关闭；断线、配置重载或重新校验立即使旧会话的运动学就绪状态失效。
- 校验通过的汇川参数、设备/型号/固件身份、来源路径与 SHA-256 保存到独立数据库快照，
  不覆盖通用品牌模板，也不在重启后仅凭缓存恢复运动能力。优化候选模型仍不自动替换生产模型。
- 通用 `TryGetCurrentPulse` 只能返回与 `AxisUnit` 对应的关节读数；汇川运动学未就绪时返回失败，
  不能把含零点和耦合的绝对编码器脉冲冒充通用脉冲。数据库轴参数缺失、部分存在、零除或非有限值
  均视为未就绪，不沿用上一轴数据。
- 主页、菜单及验收阶段 8/9 使用 `MeasureThenWeldCapabilityPolicy` 的同一入口规则。打开配置页
  不自动运动、不自动更换安全位路线；执行前再按实际参数检查所需能力：示教安全位必须支持关节运动，
  计算安全位使用直线运动，但仍必须成功读取当前关节并校验轴单位，不能跳过翻转风险检查。

### 通用关节运动专项验收（2026-09-07）

- 阶段 4 保留既有低速直线往返，另设独立的关节专项按钮与结果。默认仅 J1 增加 0.5 度、
  速度 1%，其余轴保持捕获值；外移和返回分别人工确认。需检查整个机械臂的扫掠范围，而非只看 TCP。
- 起点、轴单位、目标限位、发送前位置、完成状态和所有轴的终点回读必须验证；失败不保留猜测返回点。
  返回点仅在当前会话内使用，不能从历史记录恢复并自动运动。
- 直线 `pass` 不代表关节 `pass`。关节结果独立写入数据库并进入报告，重启中断的测试不判通过；
  没有声明关节运动能力的品牌明确提示受限，不会被软件强行开启。
