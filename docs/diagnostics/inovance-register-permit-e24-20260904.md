# 汇川寄存器写入 e24 修正记录

## 原因与修正

现场截图中第0项连接测试已通过，第5项显示许可为0，`Set_D` 返回 `e24:without permit`。这是控制许可缺失，不是管理员登录失败。

源码确认 `SetIntVar`（R/B）、`SetRealVar`（D）、`WriteCartesianRegister`（P）原先直接发送写命令，没有自行准备许可。现在在参数校验后、实际写入前统一调用品牌底层现有的 `EnsureControlPermit()`，失败即返回，不依赖先前运动或初始化留下的许可。许可归属回读不是0、1、2时拒绝继续；默认仍不强抢其它客户端许可。

业务层仍仅调用 `RobotDriverAdaptor` 的读写接口，不操作汇川协议，不为写变量隐式重连、切模式或上电。

## 验收报告与收尾修正

原报告把恢复接口返回false显示成“未执行”，并仅保留最后一次接口错误，可能覆盖最初的整数写入错误；未实际取得的回读值也会显示成默认0。

现在使用共享的 `RobotRegisterRoundTrip` 流程，分别记录初始读取、临时写入、临时回读、恢复命令、恢复回读的尝试状态、结果和错误，以及两次值一致性校验。原值读取失败时不写；开始写入后即使接口返回失败或抛出异常，仍尝试回读和恢复。恢复接口失败但回读原值一致，仍保留失败，不自动标记通过。

一项寄存器测试失败后完成本项收尾，停止后续寄存器测试；INT失败不继续REAL。前置状态读取失败时不执行寄存器测试。详细证据沿用现有验收数据库与报告导出流程。

## 验证边界

- 新增共享写读恢复的离线C++测试：正常往返、原值读取失败、各步骤失败、错误独立留存、写入结果不确定、值不一致、异常、状态标签及REAL值。
- 静态检查三类汇川写接口均在发送前验证许可，且没有隐式运动准备；验收界面仍只调用通用适配接口。
- 登录回归、15组模式组合、19组报警准备测试通过；适配层边界和验收流程检查通过。
- 本次未连接现场控制器，未读写实际寄存器，未上电或运动。现场效果需重启新Release后重新执行第5项确认，旧失败记录不会被自动改为通过。
