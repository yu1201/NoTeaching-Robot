# 寄存器现场确认后回读验收

## 流程

1. 确认机器人身份、测试变量独占预留且相关JOB/PLC任务已停止；回读空闲/完成终态。
2. 按INT、REAL顺序逐个测试：读取原值，将原值、临时值、实际变量名、端点和品牌先保存到数据库。
3. 写入成功后弹出核对窗口，保留测试值等待现场观察。汇川INT254显示为R[254]，REAL254显示为D[254]。
4. 操作者点击“现场数值一致，回读校验”后，独立回读并比较测试值；随后恢复原值，再回读验证。
5. 本变量通过且结果保存成功后才继续下一个。全部已声明的被测寄存器完成才判定本项通过；列出的其它控制能力仍不代表已执行测试。

驱动写接口自身已有的即时回读保持不变；它是写接口内部验证，不能替代现场确认后的验收回读。

## 取消、中断与记录

- 取消、关闭确认窗口、五分钟超时：不通过，不继续下一个变量，尝试恢复并独立回读。
- 写返回失败或超时也可能已改变数值，仍保留失败并尝试恢复。
- 原值保存失败不写入；最终证据保存失败不能显示通过。现场确认及时间、每步接口结果与错误写入现有数据库/报告。
- 恢复命令、回读及原值一致性都成功才清除RegisterRecovery。异常退出/断网不能保证恢复，数据库保留原值。
- 下一次第5项扫描该机器人全部历史轮次的未恢复记录。先由人工在示教器恢复原值，再点击确认进行只读核对；本次不写、不自动开始下一次测试。端点/品牌改变时拒绝核对。
- 第5项禁止人工直接改为通过。正常测试结束无需第二次笼统人工确认。

## 离线验证

共享顺序测试覆盖：等待期间保持测试值且没有验收回读、确认后回读、取消、异常、持久化失败零写入、确认后值被改变、失败ACK及恢复失败。数据库测试覆盖跨进程记录、未恢复标记将陈旧通过降为失败、重复加载不叠加提示。适配边界静态检查保留品牌中立。
