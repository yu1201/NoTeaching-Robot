# 汇川运动准备策略固化（2026-09-07）

## 现场原因

`MeasureThenWeldLog.txt` 16:14:55、16:15:11 在发送扫描下枪安全位运动前，因
“数据流准备组合尚未验证/选用”被拦截。旧代码仅在驱动内存记录连接 epoch 和选用 ID；
数据库保存的是验收报告，不是可恢复的运行策略。重启、重连必然使选用失效。
这次报错不是扫描时间轴错误。

## 固化契约

- 业务仍只调用 `RobotDriverAdaptor` 的组合测试、选用和当前策略接口。
- 无位移组合测试及恢复验证都通过后，显式“选用已通过组合”才固化；不自动选择首个通过项。
- 保存到 `robot/<内部名>/RobotPara/ModePreparation` 的 `SelectedStrategy` 单 JSON。
- 保存 schema、策略时序 revision、策略 ID、UTC 验证时间、测试证据和控制器绑定。
- 绑定包含内部机器人名、驱动、控制主机/端口、实时 `Get_RobotType` / `Get_FwVersion`。
  当前没有独立硬件 SN；不能声称相同地址、型号、固件就能唯一识别更换后的硬件。
- 使用数据库 compare-and-swap 事务，写后回读一致才提交；写入失败不宣称选用成功。
- 重连仅查询型号/固件并加载策略，不执行 Test/Prepare，不申请控制权、不切模式、不上电、不开流。
- 不依赖 FTP/运动学采集成功才恢复策略，避免将策略恢复与关节运动学能力耦合。
- 真正运行时仍检查当前控制权、任务/运动状态、急停、故障、取消与每步回读；不接管非本次建立的数据流。
  显式连接初始化仍建立模式2和伺服上电。现场固件在模式2明确拒绝 `Dsmode ON (e4)`，因此首次直连
  运动按已验收且“上电→开流”的固化组合切到对应模式；`Set_Mode` 后等待250ms稳定，再执行/确认
  `Motor ON`，随后开流。正常关流后保留该模式和伺服上电，后续直连段不再切模式或上下电；原生JOB
  启动前独立稳定恢复模式2和伺服上电。先开流再上电的组合只保留验收证据，禁止用于常驻使能生产运行。
- 身份、固件或策略版本变化、未知策略 ID、损坏记录和数据库错误均不激活旧策略。
- 重测已固化组合前先写入持久撤销标记。撤销失败不开始测试；失败重测后的旧 PASS 不得在重启后复活。
- 选用期间临时阻止新操作并检查活动任务/数据流，避免替换正在使用的退出顺序。
- 准备命令、复合状态读取、成功发布和退出清理均绑定入口 epoch，在 socket 锁内复核，禁止跨连接继续旧动作。

## 界面与升级

- 区分“本连接通过·已固化”“已恢复固化策略”“本连接已通过·待固化”，恢复策略不伪装为本次实测通过。
- 扫描下枪安全位置失败的弹窗透传机器人最近错误。
- 旧验收自由文本无可靠的端点、型号、固件、revision 绑定，不自动转为授权。
  升级后需要对所需组合测试并选用固化一次；以后同一配置重启/重连不再要求重新跑验收组合。
- 显式连接初始化现会在安全门禁通过后切换自动模式并上电，模式切换也经过稳定等待和终态连续回读。
  数据流运动首次进入时按固化组合准备；正常完成只关闭数据流并保持伺服上电。原生JOB恢复自动模式；
  断连/退出仍执行安全收尾。
  尚未以现场试验证明的其它 JOB/模式切换组合不作推定。
