# 本地账号与凭据安全

ConfigStore schema v5 将账号口令与可恢复凭据分开处理：

- 账号口令保存为自描述的 PBKDF2-HMAC-SHA256 记录，使用 16 字节随机盐、600,000 次迭代和 32 字节派生值。摘要不是可恢复凭据，不绑定 Windows 用户；旧的单次 SHA256 记录只在正确密码验证后升级，升级写入失败时拒绝登录。
- 记住密码、机器人/在线服务 FTP 密码和管理令牌使用 Windows DPAPI CurrentUser。DPAPI 的 optional entropy 绑定到 scope、module 和 key，复制到另一个字段后不能解密；保护或解密失败时没有明文、Base64 或 XOR 回退。
- 全新空数据库不携带或生成公开的默认管理员密码，而是在认证页要求首位本机用户为固定账号名 `admin` 设置至少 8 位密码；管理员新建的其他账号使用初始临时密码并设置 `MustChangePassword=1`。管理界面修改既有账号密码时默认作为最终密码直接生效，只有管理员显式勾选“下次登录强制再次修改密码（临时密码）”才保留 `MustChangePassword=1`；需要改密时，完成前不建立用户会话。
- 只有真正新建且没有账号的数据库带 `auth_initialized=0`；用户自设密码的初始管理员记录与该标志在 `BEGIN IMMEDIATE` 事务中一次性提交。既有库、未显式重建的旧空库、账号被清空或有账号但无管理员时都进入恢复状态，不能重新生成已知默认凭据。
- v4→v5 在单一 SQLite 事务中恢复旧 `Accounts.ini` 语义映射、清除旧 `PasswordBase64/SavedPasswords`，再升级可恢复凭据。未知未来 schema 或非法认证元数据直接拒绝打开，不降级覆盖。
- 认证语义版本 2 会把既有 `account/Profile` 中旧 `enc:v1` 的 PasswordHash/Role 解码后严格校验，并将 PasswordHash、Role、MustChangePassword 规范为 `encrypted=0` 的不可恢复验证元数据；缺少改密标志时强制为 1。存在账号但没有合法管理员的迁移会原子失败。
- 登录会话绑定 PasswordHash、Role 与 MustChangePassword 指纹；主页、管理栈和独立操作窗口会周期及输入前复核。账号被删除、降权或重置后，全局租约门禁立即拒绝任何新机器人操作；跨轮流程把门禁关闭视为停止请求，FTP Job 在原生文件框返回后的提交点还会同步重读账号与工程师权限。若机器人任务正在运行，仅暂时保留现有任务的安全停止/收枪，运行中拒绝主动切换登录页，确保主页固定红色 STOP 不被隐藏；任务结束后强制回登录页。
- 在线服务的升级源、FTP 目的端、FTP 密码和管理令牌只向实时有效的本地管理员会话显示并允许保存；远程删除、建目录和服务器账号管理在提交请求前再次校验本地管理员会话。
- `ConfigMigrate_Run.cmd` 对默认的原地迁移在同一数据库事务中写入待清理文件的相对路径、清理前/后 SHA256 和 `pending` 状态；之后只处理哈希仍等于已证明前态或后态的文件，全部复扫通过才改为 `complete`。中断后可安全重试；完成后新出现或已变化的凭据文件不会被自动删除，而是硬失败等待人工审查。
- 仅扩展名正好为 `.ini` 的文件可进入自动清理清单；包含凭据的 `.ini.bak`、journal、WAL、旧明文数据库备份和临时恢复文件都属于发布硬门禁。重命名为 `Accounts_backup.ini` 等仍会按节/键语义识别凭据，不依赖固定文件名；`PassCount`、`BypassQualityGate`、`CompassHeading` 等非凭据键不会因包含 `pass` 子串而误删。
- 迁移器自动生成的数据库回滚件使用 DPAPI CurrentUser 保护：SQLite 通过内存备份连接序列化，再完成 SHA256 和 DPAPI 解密回读校验后落盘；可用 `--restore-dpapi-backup <文件> --db <目标>` 恢复。正常备份流程不会生成明文 SQLite 临时快照或 `.bak`。
- 非当前 schema 的数据库旁只要仍有旧 INI/TXT，应用启动就拒绝就地升级，必须先运行当前 `ConfigMigrate`。已有 v4 数据库与磁盘旧配置并存时，迁移器也拒绝猜测合并顺序；审查备份后必须显式使用 `--overwrite` 从完整旧 `Data` 重建。
- 安装包不携带在线服务或机器人 FTP 密码。缺少密码时上传或机器人 FTP 明确报告未配置。

DPAPI CurrentUser 保护静态数据库不被其他 Windows 用户或离线复制直接解密，但不能防同一 Windows 用户权限下的恶意进程。需要把本地角色作为强安全边界时，还必须配合独立 Windows 账号、受限 NTFS ACL 或独立服务进程。

历史版本中曾进入源码或安装包的共享远程凭据必须按已泄露处理并在服务器/机器人侧轮换；从新源码删除字面量不能使旧凭据重新安全。迁移器只能治理本次原地迁移触及的文件；此前遗留的明文数据库 `.bak*`、WAL、journal、VSS/磁盘残留和外部备份仍可能保留历史值，检测到候选时属于发布硬门禁，必须限制访问并完成凭据轮换。
